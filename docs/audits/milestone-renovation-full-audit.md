## 3. Portrait integration

* Sources staged in `assets/team/` (1122 × 1402 WebP, outside `public/` so nothing is served yet).
* `npm run build:team` generates 480/800/1122 px variants into `public/assets/img/team/`.
* `team_section()` in `build_site.py` renders a 4:5 card grid on `/about` with `srcset`/`sizes`, intrinsic `width`/`height` (no layout shift), lazy loading (section is below the fold), `object-position: 50% 20%`, alt text "Portrait of <name>". A role line renders only when a verified `role` is set (none are).
* The enabled path was built and checked at 320 / 768 / 1440 px: equal cards, no facial cropping, no overflow. It was then reverted; a test asserts the page and assets stay absent while the flag is off.
* When enabled, the privacy notice adds "Team portraits are AI-edited images."
* To publish after approval: confirm consent + logo, optionally replace with authentic photography, set `TEAM_PORTRAITS_APPROVED = True`, add verified roles, run `npm run build:team && npm run build:site`.

## 4. Calculator

Engine reviewed in full (`public/js/lib/estimate.js`); 10 new tests in `tests/estimate-edge.test.js` cover inclusive boundaries (1/10 m, 1/100 m²), NaN/Infinity/negative/string/null inputs, the full option space (all finite, no price in planning mode), area-band edges, rounding, and priced-mode finiteness using a clearly labelled **test-fixture** card (not a business rate). No pricing, rates or policies were invented. Hand-off to the questionnaire is whitelisted and already tested.
