# Architecture

## Decision

Keep the starter's **static HTML/CSS/JS site** and add **Vercel serverless functions + Supabase Postgres**.
No React/Next.js migration.

**Why:** the site is ~13 content pages with a handful of interactive islands (contact form, questionnaire, planner).
Nothing needs client-side routing, SSR or a component runtime. A static site gives the best Core Web Vitals and the
smallest attack surface; the only dynamic need is a durable, secure lead pipeline, which one function covers.
Revisit if a protected admin dashboard or client portal is built (see roadmap) — that is the first feature that would
justify a framework.

## Layout

```
public/                 Vercel output directory — the only thing served statically
  *.html                generated by build_site.py (committed)
  css/site.css          original starter styles (palette aligned to brand)
  css/app.css           brand header, forms, questionnaire, planner
  js/site.js            menu + image fallback
  js/enquiry-form.js    contact form UI
  js/wizard-ui.js       questionnaire UI
  js/calculator-ui.js   planner UI
  js/lib/               pure, DOM-free logic shared with tests and (au.js) the server
  assets/brand/         approved logo pack subset + generated favicons / OG image
api/enquiries.js        POST /api/enquiries (Vercel function)
lib/                    server-only code (schema, service, stores, notifier, logger)
supabase/migrations/    SQL schema, constraints, RLS
build_site.py           static page generator (source of truth for page content)
scripts/                brand-asset generator, local dev server
tests/                  node:test unit/integration + Playwright e2e
```

`lib/`, `supabase/`, `tests/` etc. sit **outside** `public/`, so they are never served to visitors.

## Enquiry flow

```
Browser form ──POST JSON──▶ api/enquiries.js ──▶ createEnquiry()
                                 │   1 honeypot + min-fill-time
                                 │   2 zod validation (strict, AU phone/postcode)
                                 │   3 idempotency-key lookup  → return original reference
                                 │   4 per-IP-hash rate limit (DB count, 5/hour)
                                 │   5 content de-dupe (24h)   → return original reference
                                 │   6 INSERT (service role)   → fail ⇒ 503, retryable, NO success
                                 ▼   7 only now: 201 + reference
                          after store: Resend staff email (4s timeout)
                          result recorded in notification_status; failure never undoes the lead
```

Properties:

- **Success means stored.** The 201/200 response is only produced after the row exists.
- **Retry-safe.** The browser keeps one idempotency key per form session; retries return the original reference.
- **Notification is best-effort.** `notification_status` = `sent | failed | skipped | pending`, so missed emails are queryable.
- **No PII in logs.** The logger whitelists non-personal keys only (tested).
- **Raw IPs are never stored** — an HMAC with `IP_HASH_SECRET` is, for rate limiting only.
- **Fails closed.** Missing Supabase/secret env ⇒ `503 not_configured`, never a fake success.

## Data model & access

`enquiries` (status enum `new → contacted → consultation_booked → quoted → won/lost`, category enum, owner, last-contact,
notes, source, consent timestamp/version, JSONB questionnaire answers), `enquiry_notes`, `enquiry_status_events`
(trigger-maintained history) and the `enquiry_pipeline_summary` reporting view.

RLS is enabled **and forced** on all tables with **no policies for `anon`/`authenticated`**, and privileges are revoked
from those roles. Only the server's `service_role` key can read or write. This is verified by tests that run the real
migration on in-process Postgres (PGlite) and attempt every operation as `anon` and `authenticated`.

## Security headers

`vercel.json` sets CSP (`script-src 'self'`, no inline script/style), HSTS, `X-Frame-Options: DENY`,
`nosniff`, referrer and permissions policies. Pages contain no inline handlers or styles (tested). The CSP
additionally allows `raw.githubusercontent.com` for images **only while** local copies of the parent-brand
photography are missing.

## Cost calculator

`public/js/lib/pricing-config.js` holds the indicative Sydney pricing configuration (sources, tier ranges,
adjustments, timelines, GST) and `public/js/lib/price-estimate.js` is the pure engine used by the browser and by the
server (staff notification). Ranges are market benchmarks, not approved Milestone rates; every adjustment is tagged
`source` or `assumption`. See `docs/PRICING-METHODOLOGY.md`. `public/js/lib/estimate.js` is the earlier
planning-profile engine; it is retained only for the legacy `planner` planning-context section accepted by the
questionnaire and server schema.
